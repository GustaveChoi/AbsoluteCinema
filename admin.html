DATA ARCHITECTURE

从一张票，到关系模型。

一条订单记录对应一张票，多座通过购票单号关联。退款流水关联原票。

核心不变量：同一场次的同一座位，最多存在一条 pending / paid 订单。复合外键确保座位和场次属于同一影厅；cancelled / refunded 订单保留历史，不占用座位。

SQL 实例

-- READ：三表查询
SELECT o.id, u.name, s.starts_at FROM orders o
JOIN users u ON u.id=o.user_id
JOIN screenings s ON s.id=o.screening_id WHERE o.user_id=1;

-- CREATE / UPDATE / DELETE：电影维护
INSERT INTO movies(title,duration,genre,description) VALUES ('新电影',120,'剧情','演示');
UPDATE movies SET duration=125 WHERE id=4;
DELETE FROM movies WHERE id=4; -- 已有场次引用时由外键阻止

-- 防重复售票：SQLite 部分唯一索引 + 写事务
CREATE UNIQUE INDEX uq_active_seat ON orders(screening_id,seat_id)
WHERE status IN ('pending','paid');
BEGIN IMMEDIATE;
INSERT INTO orders(user_id,screening_id,hall_id,seat_id,amount)
VALUES (1,1,1,8,2500);
COMMIT;

-- 取消未支付订单，保留历史并释放座位
UPDATE orders SET status='cancelled' WHERE id=1 AND status='pending';
技术边界：本 Demo 使用 SQLite，写事务串行化；不是 MySQL 行锁压测。后续可迁移 MySQL，使用独立场次座位库存表、条件 UPDATE 和事务实现锁座。MongoDB 为可选扩展；本阶段不搭建 Hadoop。
